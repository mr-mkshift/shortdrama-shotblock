# 타깃별 특성 — 툴이 다르면 규칙이 달라진다

## 왜 따로 두나

문법은 타깃이 바뀌어도 대체로 같지만, **툴마다 물리적 제약이 다르다.**
최소 생성 길이, 클립이 끝나는 방식, 참조 이미지를 다루는 능력 같은 것들이다.

이건 작품 지식이 아니라 **툴 지식**이다. 작품이 바뀌어도 그대로 쓴다.
그래서 프로젝트 카드가 아니라 여기 둔다.

컷을 나누기 전에 이 파일에서 해당 타깃 항목을 읽는다.
길이 제약을 모르고 컷을 나누면 생성 자체가 안 되는 클립이 나온다.

**여기 적힌 것은 실사용에서 확인된 것만이다.** 추정은 적지 않는다.
새로 알아내면 아래 "적는 법"대로 덧붙인다.

## Seedance (Dreamina·即梦 / Doubao)

출력 언어는 **중국어**.

### 최소 생성 길이 — 4초

4초 미만은 생성되지 않는다. 2초·3초짜리 클립은 만들 수 없다.

컷을 나눌 때 **클립 단위가 4초 밑으로 내려가지 않게** 한다.
2초짜리 컷이 필요하면 그 컷만 따로 뽑지 말고, 앞뒤 컷과 묶어 한 클립 안에서 하드컷으로 처리한다.

한 클립 안의 컷 길이에는 제한이 없다 — 4초 제약은 **생성 단위**에만 걸린다.

### 대사가 끝나면 영상도 끝난다

Seedance는 마지막 대사 음절에서 화면을 끊는다. 편집으로 붙일 여백이 남지 않는다.
컷 끝에 **무엇을 하며 시간을 쓸지** 적지 않으면 매번 이렇게 나온다.

여백을 만드는 방법은 둘이다. 컷 성격에 맞는 쪽을 고른다.

```
자세 유지    说完后保持<자세>不动<N>秒，仅有自然呼吸；不做新动作，不说话。
             말 끝나고 N초 동안 자세·표정 유지, 새 동작 없음
             → 하드컷으로 넘길 때. 어디서 잘라도 붙는다

동작 연장    说完后<후속 동작>，<시선 처리>。
             말 끝나고 손을 내리거나, 고개를 돌리거나, 반 걸음 물러선다
             → 상황이 이어지는 느낌이 난다. 컷이 끊긴 티가 덜 난다
```

둘 중 하나는 반드시 적는다. 안 적으면 모델이 남는 시간에 동작을 지어내거나,
대사 끝에서 그냥 잘라버린다.

### 연속 생성 길이

버전에 따라 다르다. **사용자가 버전과 길이를 말했을 때만 그 값을 쓴다.**
말하지 않으면 짧은 클립 여러 개로 나누는 쪽을 기본으로 삼는다.

2.5에서 30초 연속 생성이 확인됐다. 이 경우 트림용 여유분을 붙일 필요가 없다 —
생성 길이를 곧 사용 길이로 잡고, 클립 경계를 편집 하드컷 지점에 맞춘다.

### 참조 이미지 안의 글자는 복제된다

참조 이미지에 **이미 박혀 있는** 글자는 영상에도 그대로 따라 나온다. 한글도 나온다.
없는 글자를 새로 그리라고 하면 깨진다. 난이도가 다른 일이다.

그래서 화면 안에 글자가 필요하면 **참조 이미지에 박아 넣고 복제시킨다.**
자세한 지시 방법은 `scene-space.md` 7장.

글자 내용이 도중에 바뀌면 상태별로 참조 이미지를 나눈다 — `scene-space.md` 6장.

### 자주 어긋나는 것

- 큰 배경 화면을 여러 장으로 쪼개 그린다 → `单块连续屏幕，没有拼接线` 으로 막는다
- 고정 陈设(전시대·소품)을 프레임에서 빼먹는다 → `凡取景到<위치>的镜头都必须出现，不得省略` 으로 막는다

## 적는 법

리롤하면서 알아낸 툴 특성을 여기 덧붙인다. 두 조각으로 적는다.

```
<무슨 일이 일어나는가>  →  <프롬프트에서 어떻게 막거나 활용하는가>
```

**한 번 겪은 것만 적는다.** "아마 이럴 것이다"는 적지 않는다 —
검증 안 된 항목이 섞이면 이 파일 전체를 못 믿게 된다.

특정 작품에서만 통하는 값은 여기 말고 프로젝트 카드의 `이 작품의 예외` 로 간다.
판별 기준은 하나다 — **다음 작품에서도 그대로인가.**
